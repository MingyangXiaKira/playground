AI 时代怎么学：六步闭环

每天只转这一圈。转不完就缩短题目，不要改成「先看完一门课再说」。

1 规格你先写 5 条，再问 AI
2 生成AI 出第一稿，禁止直接合
3 朗读每条指令用自己的话讲一遍
4 跑通测试失败就停，先修环境
5 攻击你写一条 AI 没写的坏用例
6 手改自己改 10 行，不让 AI 重写全文件

过关标准不是「AI 能跑」，而是「你能改，且改完还能讲」。

规格必须你写

至少写清：谁是用户、点哪一步、链上改哪个账户、谁付钱、失败时怎么回滚。规格空着就让 AI 写，等于把产品决定权交出去，后面无法审查。

讲解必须你讲

对着代码录音 90 秒，或写 8 行注释。讲不出来的函数，视为你不会。比赛评委和加速器面试问的就是这个，不是问你用了哪个模型。

手改必须你改

例如把 increment 改成 increment_by(n)，并加上最大值。AI 可以提示，但补丁必须你敲。这是「修改能力」的最小训练单位。

禁止的学法： 把 Solidity / Rust 教材从头看到尾；让 AI「做个完整 DEX」然后提交；收藏 30 个教程却从不部署；用主网真金测试。这些都会让你在 11 月交一份自己解释不了的仓库。

只记 12 条原理

用来审 AI，不是用来考试。遇到生成代码，用这张表对照「它有没有撒谎」。

#原理审 AI 时怎么用
1钱包是密钥对，不是「网站账号」AI 若把私钥写进前端或仓库，直接扔掉
2交易是签名后的指令列表问：这条交易里有几条指令？谁签了名？
3Solana 上 程序无状态，数据在账户里AI 若按以太坊「合约自己存余额」来写，模型用错了
4账户必须显式传入Accounts 结构少一个账户，运行时会炸。让 AI 列账户表
5PDA 是程序控制的地址核对 seeds 和 bump 是否和客户端一致，这是最高频幻觉
6每个账户问三句：谁签名、谁可写、谁拥有缺 signer / 缺 has_one / 缺 owner 检查 = 可被偷
7代币 = Mint + Token Account（ATA）AI 常混用 Token Program 和 Token-2022，程序 ID 必须对
8CPI 是程序调用另一个程序转账、发币几乎都是 CPI。没有 CPI 却声称「转了钱」，是假的
9存数据要付 rent，账户有固定大小AI 乱改账户结构却不升级空间，部署后写不进去
10三套网：localnet / devnet / mainnet例子里出现主网 RPC 或真 SOL，立刻停
11安全只问一句：谁能把钱转走自己写一条「攻击者调这个指令」的测试
12前端只是遥控器，链上才是真相按钮能点不算完成，浏览器里账户数据变了才算

你必须能改

2025–2026 年 AI 写 Solana 时最爱错的东西。看到就当警报：

  • 编造不存在的 crate / npm 包，或把 @solana/web3.js 1.x 和 @solana/kit 的 API 混在一个文件里
  • Program ID 乱填：System Program、Token Program、Associated Token Program 用了过期或错误地址
  • PDA seeds 在程序和前端不一致，或把 bump 写成 255
  • 用 unwrap() / expect() 处理用户输入，测试一过业务一炸
  • 「已经转账」但代码里没有任何 CPI
  • 教程还在教已废弃的 solana-install；现在应走 官方安装 和当前 Anchor 版本（以 anchor --version 为准，不要让 AI 锁死过期版本）
  • 让你把真实 SOL 打到它生成的地址，或把私钥发到聊天里
